# DESIGN-PET-LIFE：桌宠的交互分层、内在状态、连续情绪与设置面板（2026-10-09）

> 范围：本机 X11 桌宠（`l2dtest --pet`）+ 示例 LLM agent（`tools/pet_agent.py`）。
> 协议细节见仓库根 [`PROTOCOL-LLM.md`](../PROTOCOL-LLM.md)（§5.1 命令表、§5.4 事件、§7 本机桌宠）；
> 本文写**为什么这么做、具体怎么算、边界在哪**。

## 0. 起因（用户反馈 → 结论）

| 反馈 | 诊断 | 对策 |
|---|---|---|
| "感觉交互性很差" | 一切都等 LLM：从开始摸到 LLM 开口隔 20~30s；开口时说的是"事后总结"；每段 10s+ 填充动作 + 道具表情乱换；本地即时反应没有台词 | **三层交互**（§1）：本地即时层 0 延迟带台词；LLM 只在停手后补一句；闲时再演 |
| "不像个宠物，只像一个被戳会动的玩具" | 没有自己的节律和情绪连续性——同一刺激永远同一反应，戳完就复位 | **内在状态**（§2）：精力/亲密/恼火/寂寞 + 睡觉/犯困/生闷气/享受；反应取决于当下状态 |
| "参考 soullink-emotion-sdk 做动作表情管理" | 表情是离散切换（切一个 exp，3s 后硬切回） | **连续情绪 VAD**（§3）：事件只推目标，叠加层连续映射到面部/头姿，峰值才借模型表情 |
| "参考 BongoCat 的右键弹出窗口，页面换成宠物状态和软件配置" | 只有"右键双击退出"，没有可视状态与设置 | **右键菜单 + 状态与设置窗口**（§4），操作全部走协议命令 |

## 1. 三层交互

| 层 | 谁做 | 时机 | 内容 | 代码 |
|---|---|---|---|---|
| 即时 | 桌宠本地 | 每次点/搓，0 延迟 | 看向触点 1.2s + 部位动作 + **推情绪** + 一句短台词气泡 | `ZoneReact` / `PickReactLine` |
| 回应 | LLM | 用户**停手 2s** 后；两次回应 ≥10s | `mode:"replace"` 打断闲时段；≤6s、2~3 步，第一步就开口 | `pet_agent.py` 主循环 |
| 闲时 | LLM | 无互动时；平均 `llm_period`（默认 60s）×(1~1.5) | 8~15s 小日常，台词可无 | 同上 |

### 1.1 本地即时台词库

- agent 启动时让 LLM **按人设一次性**写好（`LINES_PROMPT`）：16 区 × `.click`/`.rub` × 3 句 + `angry` 4 句 +
  10 组生活场景 `life.*`（lonely/welcome/drowsy/wake/woken/sulk_start/sulk/forgive/enjoy/sleep_talk）；
  实测 shuflle 生成 43 组 130 句，耗时约 5s。
- 下发：`{"cmd":"reactions","lines":{…}}`（整体替换；每组 ≤8 句、每句 ≤60 字节；agent 侧再滤 ≤20 字符）。
- 选句：`angry`（同区连点 n≥3）→ `<区>.<click|rub>` → rub 缺省回落 `.click` → 内置兜底（每区两句）；
  避免与上一句相同。生活场景键 `life.<key>` 缺省用代码里的内置句。
- 节流：即时台词两句间隔 ≥1.5s；待选提问的气泡不被冲掉；设置项 `lines=0` 关闭全部本地台词（含生活场景）。

### 1.2 agent 节制（代码强制，`throttle`/`clamp_respond`）

| 常量 | 值 | 含义 |
|---|---|---|
| `QUIET_AFTER_TOUCH` | 2.0s | 停手多久给【回应】段 |
| `RESPOND_COOLDOWN` | 10s | 两次【回应】最短间隔 |
| `RESPOND_MAX_DUR` | 6s | 【回应】段截断；被截时补一步收回姿势+表情 |
| `MAX_SPEAK_PER_SEG` | 2 | 每段台词上限 |
| `MAX_EXPR_PER_SEG` | 2 | 每段换表情上限（`null` 复原不算）|
| `QUESTION_COOLDOWN` | 300s | 提问（options）最短间隔；每段 ≤1 个，且必须挂在 speak 步上 |
| `QUESTION_WAIT` | 25s | 提问后等选择；期间不发闲时段 |

- 选项提问是 `【回应】`/choice 续戏之外唯一会"等用户"的情况；设置 `llm_questions=0` 直接剥掉所有 options。
- 犯困/睡着时：不发闲时段；睡着时被碰的 backlog 丢弃（本地处理迷糊/被吵醒，醒了会有 mood 事件）。
- `hover` 不打日志、只作下一段的弱上下文（"鼠标刚在你的 X 附近"）。
- 提示词约束：表情优先用 `emotion` 键；道具/装扮类表情（眼罩、手柄、麦克风、猫猫手、星星）除非剧情需要不用——
  **仅提示词约束，代码没拦**（哪些算道具无法自动判定；要硬拦需 profile 加黑名单，见 §6）。

> **触摸动词（2026-10-10 文案统一，`player/src/PetVerbs.h` / `pet_memory.touch_verb`）**：点击 = **戳**（手 = **牵**、脸 = **捏**）；
> 拖动 = **揉**（头、手 = **摸**）。日志、最近动态、亲密度扣分提示、agent 的互动摘要与提示词、记忆里的习惯统计、内置兜底台词都按这张表取词。

## 2. 内在状态（`PetLifeTick` / `LifeTouch`，仅 `--pet`）

### 2.1 数值（0..1）

| 量 | 初值 | 变化 | 存盘 |
|---|---|---|---|
| `energy` 精力 | 0.8 | 醒着 −1/2400 每秒（夜间 23:00–6:00 −1/900）；睡着 **+1/1500**（约 25 分钟回满）；**每次互动都消耗**：戳 −0.015、摸 −0.01、猜拳 −0.04、讲笑话 −0.02；犯困被碰 +0.1（但精力 <0.3 时不回、反扣亲密度）；你回来 +0.15 | 否（每次启动 0.8）|
| `affection` 亲密 | 0.3 / 存档 | **边际递减**：实际增量 = g×min(1,(1−当前)×1.6)，当前 <0.25（冷淡）时再×0.5（信任慢慢重建）（g：摸头脸手 0.015；摸头哄好 0.03；睡梦中被摸 0.02；牵手 0.01）；点胸/胯 −0.01；**累了还被折腾**：精力 <0.3 时每次互动 −0.02（线性，不递减）+ 恼火 +0.06，她抱怨一句（8s 内一次）且不做开心反应，笑话不讲；**久别回落**：离开超过 1 天，每天 −0.02（最低 0.3）| **是** |
| `annoy` 恼火 | 0 | 点击 +0.04（胸/胯 +0.22；连点 n≥3 每多一下 +0.12；亲密 >0.7 且非敏感区减半）；摸头 −0.08；自然消 −1/35 每秒（生闷气时 −1/90）| 否 |
| `lonely` 寂寞 | 0.2 | 醒着且 45s 没被碰：**+1/1200 每秒**（约 20 分钟满）；被碰 −0.25；回答她的问题 −0.3；猜拳 −0.2；主动找你后 −0.35 | 否 |

> **睡眠省 token（2026-10-10）**：她**睡着**即暂停一切 LLM 调用（对话段、记忆归纳/压缩、台词库/题库/笑话补货）；
> **只有主人点她**（醒着时的 click，或戳醒 `被戳醒`）才恢复。自己睡饱醒来（`睡饱了`）仍暂停——只用本地台词库；
> 拖动（摸/揉）不算唤醒。暂停期间面板要求的"重新生成性格 / 立即压缩记忆"记下，醒来后补做；`LlmClient` 层另有兜底开关
> （`LlmSetPaused`），任何遗漏路径都直接失败不发请求。`agent_info.paused` → 面板主视觉显示"LLM 休眠 · 点她唤醒"。
> **切语言 = 新开一轮对话**（2026-10-10）：`lang_changed` 时与重写完成后都清空多轮上下文（`_history`、上段警告、待答问题）；
> 另外 `_history` 记着写它的语言，发请求前发现与当前语言不同也会整段丢掉——否则 LLM 照着上文继续用旧语言回。
> **日/英模式不再冒中文**（2026-10-10）：① 根因——agent 启动时先生成即时台词库/开性格题库笑话、**后**读配置，且桌宠刚启动时
> status 还没有 str 段 → 每次启动都按默认中文生成；现改为先读 status（等到有 `str` 段，最多 ~3s）再生成，并打印"台词语言：xx"。
> ② 兜底——`SpeechLangOk`（`PetSpeech.h`）逐句校验：日语不许出现简体专用字（脸/说/们/吗/啦…）且长汉字串必须带假名，英语不许有汉字/假名；
> 台词库、对话台词（含选项）、笑话（生成与下发）、题库都过这一关，不合格丢弃（缺组用桌宠内置本地化台词兜底）。
> ③ 台词库输出坏 JSON 时取最外层 {…} 并重试一次。
> **名字与称呼**（2026-10-10，面板「模型」页）：她的名字 / 小名 / 她怎么叫你——每个模型一份，存在性格文件
> （`personas/<指纹>.json` 的 `user_name` / `user_nick` / `user_call`，重新生成性格时保留）。协议 `{"cmd":"names","name","nick","call_user"}`
> → 内置 agent `names_set`：落盘、上报（`persona.name/nick/call`）、**新开一轮对话**、台词库按新叫法重写（睡着时等点醒）。
> 进提示词：性格段写明名字/小名，"称呼主人一律叫「X」，优先于记忆里的任何称呼"；台词库/题库/笑话的角色描述同样带上。
> 本地内置台词里的"主人 / ご主人さま / Master"在桌宠端换成设定的称呼（`ApplyCall`）。面板主视觉与右键菜单标题用她的显示名。
> **选项带能力动作**（2026-10-10）：LLM 下发的气泡选项可附 `do`（能力表里的动作/表情/情绪/一句短台词），主人一点就在桌宠本地
> **零延迟**演出，再把 choice（含 `did`）交给 LLM 接着演；提示词要求"让选项和她能做的事挂钩"（有手柄表情 → "一起打游戏"）。
> 实测：点"打游戏" 0.4s 内手柄表情 + hop + 兴奋 + 台词全部生效，LLM 续戏接着打游戏的话题；`do` 里的非法 fv 收到时即报 warning。详见 PROTOCOL-LLM。
> **台词不带日期**：记忆里的时间戳（`10-10 02:09–02:11`）只用于存盘；进提示词前、台词/台词库/笑话/问题输出后都经
> `StripStamps`（`PetSpeech.h` / `pet_memory.strip_stamps`）去掉，提示词也明令不写日期（此前 LLM 把"称呼：10-10 …"里的 10-10 当成了主人名字）。
> **累了以后的后果链**（2026-10-10）：精力 <0.3 = 累了 → 每次互动亲密 −0.02、恼火 +0.06、抱怨、不做开心反应 →
> 恼火 ≥0.7 → **生闷气**（背过身，此后亲密不再掉；摸头慢慢哄好）→ 生闷气时精力 <0.25 且 20s 没人碰 → 气着睡着；
> 任何状态精力 ≤0.02 → **累趴直接睡着**，精力回到 0.3 前**戳不醒**（只嘟囔 Zzz）→ 睡到 0.95 自己醒。
> 亲密 <0.25：被碰时 65% 概率回冷淡台词（"……嗯。""别碰我。""我们不太熟吧。"）。
> 2026-10-10 调参原因：原来精力睡 4 分钟回满、寂寞 2.5 分钟就满、亲密度只涨不跌 → 状态页三条几乎永远顶满，没有信息量。
> 亲密度在面板上改显示为**关系等级**（陌生 < 0.3 ≤ 认识 < 0.5 ≤ 熟悉 < 0.7 ≤ 亲近 < 0.85 ≤ 亲密 < 0.95 ≤ 挚友）。

存盘：`~/.local/state/l2dpet/<模型指纹>.json` = `{affection, touches, last_seen, first_seen, rps:[平,主人赢,她赢], zones:[[点,搓]×16]}`，
每 30s 原子写（tmp+替换）。`first_seen` 缺失时取 agent 记忆 `habits.json` 的 `first_seen` 与 `last_seen` 中更早者。
**按模型指纹分档**——换模型 = 另一只宠物，记忆不共享。

**状态页反馈数据**（`panel_state.state.life`）：`feed`（最近动态 ≤40 条 `[unix秒, kind, 文本]`，kind = state/say/llm/touch/game/emo，
同部位同手法 8s 内合并"×n"）、`emo_hist`（每 10s 一个 `[愉悦, 唤醒]`，≤90 个 = 15 分钟）、`zones`（`[中文名, 累计点, 累计搓, 本次点, 本次搓]`）、
`rps`、`first_seen`、`state_for`、`idle`、`since_touch`、`sleep_on`、`sleep_after`、`work`、`work_limit`、`seek_on`。
面板据此画：关系等级胶囊 / 猜拳战绩 / 每条状态"怎么影响她"的说明 / 接下来（犯困倒计时、醒来预估、休息提醒、主动搭话进度）/
情绪曲线 / 最近动态时间线 / 被摸部位分布。

"用户在不在" = **全局鼠标是否在动**（`XQueryPointer`，>3px 算动）。`user_idle` 秒数随 status 上报。

### 2.2 状态机

```
            精力<0.25 或 (鼠标静止>sleep_after 且 没被碰>sleep_after)，且没被碰>20s，且没有 LLM 段在演
  awake ──────────────────────────────────────────────▶ drowsy ──(45s 没被碰)──▶ asleep
    ▲  ▲                                                   │ 被碰 / 你回来(鼠标静止>60s后又动)     │ 戳两下(6s内) / 睡饱(精力>0.95 且睡≥60s)
    │  └───────────────────────────────────────────────────┘                                      │
    │◀─────────────────────────────────────────────────────────────────────────────────────────────┘
    │  annoy≥0.7（点击时判）
    └──────▶ sulk ──(摸头/脸/手 哄到 annoy<0.3：原谅)──▶ awake
                 └─(自然消到 annoy<0.15：气消了)──▶ awake
```

| 状态 | 表现（每帧持续写通道；进入/离开时释放非演出的头眼眉嘴通道）| 触摸 |
|---|---|---|
| awake | 正常；**享受**：2.5s 内连续摸头/脸/手 → 眯眼 −0.6、嘴角 +0.9、头往手侧歪 ±7°，不重播动作，4s 一句 `life.enjoy` | 首次摸 = 默认区域反应；点击按 2.1 记账，可能进入 sulk |
| drowsy | 眼 −0.5，7s 周期里 2s "点头打盹"（眼 −0.9、头 −14°）；进入时打哈欠（新内置动作 `yawn`）| 任意触摸 → awake + 摇头 + `life.unsleepy` |
| asleep | 眼 −1、头 −15°±2 慢呼吸（1.25 rad/s）、身体轻晃、看向下方；10~18s 冒 "Zzz…"（1/5 概率梦话，只出气泡不动嘴）| 摸头脸手 = 睡梦中笑（嘴角 +0.8，3s）；戳 1 次 = 眼皮动 + `stir`；6s 内第 2 次 = 被戳醒（精力 <0.4 有起床气：annoy +0.25、情绪 sulky）|
| sulk | 头转向**鼠标反方向** ±30°、低头 −6°、身体 ±9°、皱眉 −0.6、撇嘴 −0.7；视线看远侧；annoy<0.5 后每 8~14s 偷瞄鼠标 0.8s | 戳 = 摇头 + "哼。"（annoy +0.1）；摸头脸手 = annoy −0.18，<0.3 原谅（害羞 + 一句）|

自主行为（awake、无 LLM 段时）：

- **欢迎**：鼠标静止 >300s 后又动 → 看向鼠标 + hop（亲密 >0.5）或点头 + `life.welcome`。
- **寂寞找你**：`lonely>0.6` 且鼠标 20s 内动过 → 看向鼠标 3s + `wave_big`（无臂模型回落 `hop`）+ `life.lonely`；
  冷却 120~210s。设置 `seek=0` 关闭。
- **好奇瞄一眼**：鼠标在别处移动 → 每 15~40s 看向鼠标 1.6s（鼠标在身边时本来就跟随）。
- **开场招呼**：启动 1.5s 后按存档：首次 / 离开 >12h（亲密 >0.6 撒娇、否则冷淡）/ 其它"又见面啦"。

上报：状态变化推 `{"event":"mood","state","why","energy","affection","annoy","lonely","emotion":{…}}`；
另每 20s 推一次 `why:"tick"`；`status.mood` 同结构（多 `user_idle`）。

## 3. 连续情绪（`EmotionTick`；参考 soullink-emotion-sdk，Apache-2.0）

### 3.1 模型

- 状态：`cur`、`target`、`drift`（三轴 V 愉悦 / A 唤醒 / D 支配，各 −1..1）+ `hold` 秒。
- **推**（`EmotionNudge(name, intensity)`）：`amt = min(0.96, (0.28 + 0.58·i)·reactivity)`，
  `target += (preset − target)·amt`，`hold = max(hold, 4 + 12·i)`。
- **逼近**：`cur += (target + drift − cur)·(1 − e^(−1.6·dt))`。
- **回落**：hold 归零后 `target += (base − target)·(1 − e^(−0.08·dt))`（约 12s 时间常数）。
- **性格基线** `base`：V = 0.08 + (affection−0.5)·0.35，A = (energy−0.6)·0.5，D = 0；
  asleep → (0.15, −0.85, −0.1)；drowsy → A=−0.6；sulk → 基线 = `sulky` 且 hold 至少 2s（生闷气期间情绪不散）。
- **环境漂移**：每 1.7~5.9s 换一个 ±0.04（A×0.82、D×0.68）的小目标，以 0.62/s 逼近——情绪不完全静止。
- 原型（与 soullink 一致，另加 `sulky`）：

| 名 | V | A | D | 名 | V | A | D |
|---|---|---|---|---|---|---|---|
| calm | .25 | −.45 | .2 | tired | −.25 | −.7 | −.3 |
| happy | .75 | .45 | .35 | sad | −.65 | −.45 | −.5 |
| excited | .85 | .85 | .45 | anxious | −.6 | .7 | −.55 |
| shy | .35 | .6 | −.45 | angry | −.7 | .75 | .55 |
| affectionate | .65 | .1 | .1 | surprised | .18 | .78 | −.08 |
| curious | .35 | .55 | .2 | sulky | −.45 | .2 | .35 |
| confused | −.1 | .35 | −.3 | neutral | 0 | 0 | 0 |

  中文别名：开心/高兴/兴奋/害羞/亲昵/好奇/困惑/困/难过/伤心/紧张/生气/惊讶/平静/赌气。
- **主导情绪名**：强度 `mag = (|V| + 0.82|A| + 0.64|D|)/2.46`；<0.06 → neutral；<0.2 → 淡名
  （content 愉快 / calm / uneasy 不安 / low 有点低落 / curious）；否则规则（shy/anxious/angry/excited/calm）→
  最近原型（加权距离 1.08/0.88/1.28，阈 0.92）。

### 3.2 输出（叠加层，加在动作与眨眼之上）

在 `ApplyBodyChannelsPre` 里、动作片段叠加之后写各通道的 `extra`（`WriteBodyChannel` 是"当前值 + out"，
所以不覆盖眨眼/动作；缺的通道自动跳过）。记 pos/neg/aro/calm/dom/sub 为各轴正负部分，`g = expr_gain`：

| 通道 | 值 |
|---|---|
| `mouth.form` | (0.95·pos − 0.85·neg)·g |
| `brow.l/r`（高低）| (0.45·aro·pos + 0.35·neg·sub − 0.55·neg·dom)·g |
| `brow.l/r.form` | (0.5·pos − 0.9·neg·(0.4+dom))·g |
| `eye.l/r` | (0.18·aro − 0.3·calm − 0.22·pos·(1−aro))·g |
| `head.y`（°）| (7·dom·(0.3+aro) − 9·sub − 5·calm·neg + 3·aro·pos)·g + 脉冲 |
| `head.z`（°）| −7·pos·sub·g + 脉冲 |
| `cheek`（新标准通道 → `ParamCheek`）| 1.1·pos·(sub + 0.4·aro)·g |
| `body.y` | 2.5·aro·pos·g |

- **微动脉冲**：`(|ΔV|+|ΔA|)/dt > 0.9` 且距上次 ≥1.2s → 0.7s 半正弦包络：head.y ±(≤3)·1.6°（唤醒升=抬、降=沉），
  head.z ±2.5°（方向随机）。
- **峰值借模型表情**（`native_expr=1` 且 mag>0.3）：happy/excited/affectionate→开心，shy→害羞，angry/sulky→生气，
  surprised→惊讶，sad→难过（经 `StartEmotion` 的别名表，如 爱心/Smile、脸红/Blushing）。
  **只在没有别的表情时套**（`_expressionIndex<0` 或就是自己上次设的）；mag<0.22 且无对应情绪时只清**自己设的**那个。
  LLM/菜单指定的表情不会被情绪引擎清掉。

### 3.3 接入点

- 区域反应：原来"切表情 + 3s 复位"改为 `EmotionNudge(区域情绪, 搓 0.55 / 点 0.7 / 连点≥3 0.95)`。
- 生活：被吵醒（sulky/surprised 0.7）、寂寞（sad 0.35）、欢迎（excited/happy 0.7）、享受（affectionate 0.5）、
  进入 sulk（angry 0.9）、被哄好（shy 0.8）。
- 协议：单项 `{"cmd":"emotion","name":"shy","intensity":0.8}`；时间线步 `"emotion":"happy"` 或 `{"name","intensity"}`；
  未知名 → 警告 `未知情绪`。

## 4. 右键菜单 + "状态与设置"窗口（`PetPanel.hpp`；参考 BongoCat）

> **2026-10-09 夜更新：本节整体已被 §12 替代**（右键菜单、托盘、气泡、设置窗口全部改由 EUI-NEO 进程 `l2dpet-ui` 负责，`PetPanel.hpp`/`PetTray.hpp` 已删除）。下面的菜单项与配置键仍有效；

### 4.1 架构

```
播放器 ──PanelStateJson (2Hz)──▶ IPort::SetPanelState ──▶ Panel（解析 JSON，重画）
   ▲                                                         │ 用户操作
   └──── PetCommand(行) ◀── 主循环 ◀── IPort::PollPanelCommand ◀┘   （协议命令行，与 LLM 同一套）
```

- 面板**没有私有后门**：开关/滑块 → `config`；按钮 → `touch`/`mood`/`emotion`；菜单 → `expression`/`action`/`config`。
  执行结果打到桌宠日志 `[panel] <命令> → <回执>`。
- 窗口类配置（不透明度/置顶/穿透）由 port 在 `SetPanelState` 里比对后应用：
  `_NET_WM_WINDOW_OPACITY`、EWMH `_NET_WM_STATE_ABOVE`（ClientMessage add/remove）、XShape 输入区域清空。
- 绘制：背景与控件走软件 SDF（预乘 ARGB 浮点画布，圆角/描边/阴影/心形/胶囊抗锯齿），`XPutImage` 上屏后
  Xft 画字（`sans` 10.5/9/粗 11/粗 15/粗 20）。配色取 BongoCat 浅色调色板（底 #F0F4F9、卡 #FFF、强调 #54AEFF、粉 #F77DAA）。
- 菜单：override-redirect ARGB 窗，抓指针（`owner_events=False`：点菜单外 = 关）+ 键盘（Esc 关）；
  弹出后 0.25s 内的松开不算选择；子菜单**原地替换**（顶行"返回"），不级联。
- 设置窗口：受 WM 管理的 ARGB 窗，固定 760×540；关窗/Esc = 收起（不退出桌宠）；状态推送时重画，
  拖滑块时本地先改值并 ~8Hz 下发、松手再存（推送的旧值不会把滑块顶回去）。

## 6. 边界与已知限制（务必读）

**感知**
- "用户在不在"只看**鼠标**。只敲键盘不动鼠标 = 被当成离开 → 可能犯困睡着、回来时被"欢迎"。
- 夜间判定用本机本地时间 23:00–6:00；时区/休眠唤醒后的 `_perfClock` 跳变未特殊处理（dt>1s 的帧整帧跳过）。
- `touch` 命令把点落在包围盒的代表点（头 6%/其它 12% 高度处），不是真实区域中心；只用于面板/调试。

**状态与情绪**
- 精力、恼火、寂寞、情绪**不存盘**，每次启动从初值开始；只有亲密度/累计互动/上次见面存盘。
- sulk/asleep/drowsy 期间生活层**每帧**写头/眼/眉/嘴通道：LLM 段里对同通道的 `pose.parts` 会被压住（agent 在犯困/睡着时本来不发段；生闷气时仍会发，头部姿态以生活层为准）。
- 情绪叠加层与 LLM 指定的 `expression` 会**叠加**（例如表情文件已经笑 + 叠加层再加嘴角）——幅度靠 `expr_gain` 调，未做互斥。
- 峰值借表情依赖模型的表情命名（`StartEmotion` 别名表）；没有对应表情的模型只靠叠加层。没有 `ParamCheek` 的模型没有脸红。
- 无手臂骨架（swing/none）的模型：`wave_big` 等带臂动作不可用，自动回落 `hop`；`stretch_up` 回落 `yawn`。
- 道具类表情只靠提示词约束，代码不拦。

**LLM / agent**
- 台词库在 agent 启动时下发、存在桌宠内存：**桌宠重启后台词库丢失**，需重启 agent（桌宠没起来时 agent 会直接连接失败退出，需等桌宠端口就绪再启）。
- 每次 LLM 调用约 1~2s（DeepSeek 实测）；【回应】段因此最快在停手后 ~3s 出现——"当下"靠本地层。
- API Key 只经环境变量 `LLM_API_KEY` 传入，不写配置文件，面板里也不能编辑（无文本输入框）。

**面板 / 窗口**
- 面板状态推送写在主循环的 `ctl != NULL` 分支里：**不带 `--ctl` 启动时面板拿不到状态**（菜单首行/勾选为空，设置窗口数值为默认）。
- 只有浅色主题、只有中文、固定 760×540（未按 HiDPI 缩放）；字体靠 fontconfig 的 `sans`（需有 CJK 字体）。
- 菜单抓指针失败（极少，如别的程序正抓着）时，点菜单外不会关闭——选一项或按 Esc 关闭；子菜单不滚动，
  表情/动作超过约 25 项会超出屏幕。
- 置顶依赖 EWMH、不透明度依赖合成器（mutter 实测可写入属性；其它 WM 未验证效果）。
- **鼠标穿透**开启后桌宠收不到任何点击（不能拖、不能右键）：从菜单开启会同时打开设置窗口作为回头路；
  启动时**不继承**穿透（发现存档为 1 会自动改回 0）。
- 多显示器：菜单位置按整个 X 屏幕尺寸夹边，未按单个显示器处理。
- 截图注意：`xwd` 对受 WM 管理的 32 位窗口会报 24bpp 却按 4 字节/像素给数据，直接解析会横向压缩成 3/4；
  验证用屏幕抓取（ffmpeg `x11grab` 按窗口绝对坐标裁）。

**板卡**
- 面板只在本机 pet port 实现；RK3506 板卡（LVGL 桌面）没有对应 UI。生活层/情绪/`config` 等在播放器内，
  板卡侧照 PROTOCOL-LLM §8 的转发方案即可用协议驱动，UI 需在 LVGL 侧另做。
- 生活层与情绪只在 `_isPet`（port 名为 `pet`）时运行；板卡 drm/shm 输出下不生效（需要时把开关改成配置项）。

## 10. 长期记忆 v2（2026-10-09 晚；`tools/pet_memory.py`）

### 10.1 为什么要改（v1 的实际问题）

v1：每段交互攒一条要点 → 每 6 段让 LLM 归纳进单文件 `~/.config/l2dpet/memory.md`。实跑一天后的记忆：

| 问题 | 现象 | 原因 |
|---|---|---|
| 不了解主人 | "关于主人"一直是"（还不了解）" | 主人没法跟她说话；没有任何"了解主人"的输入 |
| 流水账 | "最近发生"全是"主人点了我的左手…" | 每次戳/摸都进归纳原料 |
| 串戏 | 换成 Natori 也"记得"你戳过 shuflle | 单文件、全角色共享 |
| 会丢 | 没攒够 6 段就关 agent，要点全没；压进"更早"后细节永久消失 | 要点只在内存；没有归档 |
| 看不出来 | 用户感觉不到她记得 | 记忆只被动注入上下文，没有"叙旧"的时机 |
| 隐私 | `memory.md` 权限 664 | 普通写文件 |

### 10.2 分层存储（全部人可读、可手改；目录 0700、文件 0600、tmp+rename 原子写）

```
~/.config/l2dpet/memory/
  owner.md                     关于主人 —— 所有角色共享（≤700 字）
  chars/<指纹>.md              我和主人之间 —— 每个角色一份：## 最近发生 / ## 更早（≤1600 字）
  chars/<指纹>.habits.json     习惯统计（程序算，不经 LLM）：各部位点/搓次数、24 小时分布、见面次数、
                               首次见面日期、上次见面时间、最近 12 次选项回答
  chars/<指纹>.pending.jsonl   待整理要点（每条 {d,w,text}，**随时落盘**，agent 被杀也不丢）
  chars/<指纹>.episodes.jsonl  归档：每次归纳用过的原始要点 + 本轮触摸统计（只追加，不删）
```

- `<指纹>` = 模型指纹（`model:0x…` 去掉前缀）：同一模型换目录/改名（如 shuflle ↔ 舒芙蕾）仍是同一个"她"，
  与桌宠亲密度存档 `~/.local/state/l2dpet/<指纹>.json` 同口径。
- **自动迁移**：首次运行发现旧 `memory.md` 且当前角色还没有文件 → "## 关于主人"段进 `owner.md`，其余进
  `chars/<当前指纹>.md`，原文件改名 `memory.md.migrated`（0600）留底；"上次见面"取旧文件修改时间
  （不会把老朋友当初次见面）。

### 10.3 什么进记忆（原料与权重）

| 来源 | 去向 | 权重 |
|---|---|---|
| `click`/`rub` 事件 | **只计数**进 habits（部位、小时）；归纳时附一行"本轮身体互动统计" | — |
| `choice`（主人在选项里的回答）| habits.choices + 要点"主人回答了我的问题：<问题>→选了「<答案>」"| **2** |
| mood：被戳烦了 / 被哄好 / 被戳醒 | 要点"我在生闷气了（被戳烦了）"… | **2** |
| mood：气消了 / 寂寞找你 | 要点 | 1 |
| mood：犯困、睡着、睡饱、被碰醒、指令、tick | **不记**（日常节律，会刷成流水账）| — |
| 【续戏】【重逢】段她说的话 | 要点"（续戏）我说：…" | 1 |
| 【回应】【闲时】段 | 不记（触摸已计数；闲时是她自言自语）| — |

### 10.4 归纳（consolidate）

- 触发：待整理**权重和** ≥ `--memory-every`（默认 6）；或有待整理/有本轮触摸、且距上次归纳 ≥ `--memory-idle`
  （默认 1200s）；或启动时 pending 非空（上次没整理完）；或 `--memory-tidy`（按当前规则把现有记忆重整一遍）。
- 每次都**从磁盘重读** owner.md / chars/<指纹>.md 再交给 LLM——保留主人的手改。
- 输出 `{"owner":…, "us":…}`，规则（提示词 `CONSOLIDATE_PROMPT`）：
  - owner **宁缺毋滥**：只收①主人亲自表达过的（选项回答、称呼、说过的喜好/讨厌）②约定
    ③统计里稳定的规律，写成"（看起来）…"、最多 2 条。不写一次性事件、不揣测主人心理、不写占位行。
  - us：`## 最近发生`（≤10 条、按天合并身体互动）+ `## 更早`（压缩短句）；第一人称。
- 校验：us 缺"## 最近发生"段 → 丢弃本次结果（要点留在 pending 下次再试）；owner 缺标题自动补。
- 成功：写两份文件、pending 追加进 episodes、清空 pending、推面板、标记台词库待刷新（≥`--lines-refresh` 秒后带新记忆重生成）。
- 用 temperature 0.3；失败记一条"记忆"类交互日志（面板"对话 → 交互日志"可见），不重试风暴（同样按 `--memory-idle` 节奏）。

### 10.5 用记忆（注入 + 召回 + 让人看得见）

- **注入**：每段生成的上下文 = owner + 我们之间 + 习惯（一句人话，程序生成，如"主人最常摸头部 67%、戳脸部 33%
  （共 9 次）；常在 18–20 点来找我；从 2026-10-09 起见过 3 次面；主人选过：「…」→…"）。
- **召回**：用当前情境（【回应】/【重逢】/选项文本）在 episodes 里按**字二元组余弦**找最相关的 ≤3 条旧事
  （阈值 0.12；和工作记忆大半重合的跳过）→ 作为"可能相关的往事（归档）"附上。压进"更早"的细节因此不会永久消失。
- **叙旧（让记忆被看见）**：
  - 启动时：离开 >30 分钟 → 第一段是【重逢】：一句招呼 + 自然提一件记忆里的事（不列举）；完全没有记忆 → 初次见面自我介绍。
  - 运行中：桌宠本地"你回来啦"后推 `mood why:"你回来了（离开 N 分钟）"` → agent 接一段【重逢】。
- **主动了解主人**：owner 里"主人亲口说过的"条目 <3（默认称呼"主人"和"（看起来）"推断不算）且允许提问、
  过了提问冷却 → 闲时段提示 LLM 用 options 问一个了解主人的小问题（称呼/作息/喜好），附上问过的问题防重复。
  主人选了 → 权重 2 要点 → 下次归纳进 owner → 所有角色共享。实测首段即问"主人～我到现在还不知道该怎么叫你才好呀"
  （叫主人就好 / 叫我哥哥 / 随便叫）。
- **离线台词库**也带记忆生成（每组最多 1 句呼应记忆）。
- **面板**：行为 → 记忆 → 记忆本页显示 owner + 我们之间（小标题 `## · 最近发生`）+ 习惯 + "还有 N 条待整理"。

### 10.6 边界与已知限制

- 主人仍然**不能打字**跟她说话：了解主人只靠选项回答 + 行为统计。要真正对话需加文本输入（面板/气泡输入框，
  中文需 XIM 输入法支持），未做。
- 召回是字面相似（二元组），不是语义检索；同义不同字的旧事召不回。归档只追加，长期使用会增长
  （每条 ~150 字节，召回只扫最后 2000 条）。
- 归纳完全依赖 LLM 守规矩：已加结构校验，但内容层面（如把她自己的话当成"约定"）仍可能不准——可手改文件，
  或改了规则后跑 `--memory-tidy`。
- 习惯统计的"几点常来"按 agent 收到的触摸事件计时，不是真实在场时间；"见面次数"= 离开 >30 分钟后再次启动/心跳。
- 删除/遗忘：没有面板按钮；直接删 `~/.config/l2dpet/memory/` 下对应文件即可（owner.md 删了 = 所有角色都忘了主人）。
- 记忆只在 `--llm` 下读写；`--no-memory` 全关；`--demo` 不碰记忆。
- 记忆内容会作为提示词发给所配置的 LLM 服务商（与对话内容同一通道）。

## 11. 高分屏与 VTS 格式模型（2026-10-09 夜）

起因：白天 1080p 正常，晚上换到 3200×2000（GNOME 200%，`Xft.dpi: 192`）后"模型和窗口都异常"。实际是两件独立的事：

| 现象 | 根因 | 修复 |
|---|---|---|
| 角色身上满屏版权字样、表情 0 个 | 重启清掉了 `/tmp/l2dm`（补全过的副本），改用的 astrbot 副本 / 发货包是 **VTube Studio 格式**：`model3.json` 不登记 `Expressions`/`Motions`（VTS 靠 `.vtube.json` 热键引用同目录的 exp3/motion3）→ 作者的"水印"开关表情没注册，关不掉 | `ReadModel3()`：缺 `Expressions` 就把目录里 `*.exp3.json` 全登记（名=文件名去后缀），缺 `Motions` 就把 `*.motion3.json` 登记进 Idle（名含 idle）/Extra；只改内存副本。Load 与水印参数收集都走它。日志 `[model] VTS 格式补全：从目录登记 12 个表情、1 个动作` |
| 设置窗口/菜单文字挤爆、气泡比例不对 | 布局按 96dpi 写死像素，字体却用 `size=pt` → Xft 按 192dpi 渲染成 2 倍 | 见下 |
| （潜在）模型糊/锯齿 | 渲染固定 360×640，再最近邻放大到窗口 | 渲染分辨率 × 缩放倍数 + 双线性 |

高分屏方案（`PortX11Pet.cpp`；当时的 `PetPanel.hpp` 已删除，菜单/气泡现由 `l2dpet-ui` 按事件里的 `scale` 处理）：

- **缩放倍数** `_ui` = `L2D_UI_SCALE` 环境变量 > `Xft.dpi`/96 > 1，钳 [1,3]；启动日志 `[port:pet] 屏幕缩放 2.00×`。
- **桌宠窗口**：初始尺寸 = `--size` × `_ui`（360×640 → 720×1280）；渲染分辨率 = 窗口尺寸，模型按物理像素清晰渲染，
  物理大小与 1080p 一致；`zoom` 配置照旧乘在上面。窗口≠渲染尺寸时用 **双线性**（`SoftScaleBilinear`，预乘 ARGB 逐通道插值）。
- **面板（菜单 + 设置窗口）**：所有布局继续用**逻辑像素**；`Canvas.s = _ui`，SDF 在逻辑坐标里求值、距离换回物理像素求覆盖率
  （边缘始终 1 物理像素抗锯齿）；字体按 `pixelsize = pt×96/72×_ui` 打开（不用 `size=`，否则被 Xft.dpi 再放大一次）；
  `TW()` 返回逻辑宽度；`Text()` 逻辑→物理；鼠标事件先 `Logical()` 换算再做命中/滑块。设置窗口 760×660 逻辑 → 1520×1320 物理。
- **气泡**：缩放 = 角色 zoom × `_ui`；字体同样改像素字号；位置夹在 `_NET_WORKAREA` 里（不再盖住 GNOME 顶栏/Dock）。
- **播放器里按 360×640 写死的像素阈值**改为按渲染宽度等比（`PxK() = 渲染宽/360`）：东张西望目标点、搓揉最小位移、
  "鼠标动了"阈值、"鼠标在人物附近"边距。
- **性能**：2× 屏渲染像素 ×4；板卡口径的光栅化线程上限 4 只有 16fps。pet 模式未显式 `--threads` 时用 min(核数, 8) → 30fps 封顶。

模型放哪：**`~/.local/share/l2dpet/models/<名字>/`**（桌宠模型库，托盘/右键菜单可切换）；不要放 `/tmp`（重启即丢）。
发货包解压到这里即可，VTS 格式自动补全，不用手改 `model3.json`。

边界：
- 缩放倍数在启动时取一次；运行中改系统缩放 / 跨不同 DPI 的显示器拖动，需要重启桌宠。
- 多显示器取整个 X 屏的 `Xft.dpi`（X11 下本来就只有一个全局 dpi）。
- VTS 补全只补"缺了的整段"：`model3.json` 已有 `Expressions` 但漏登记个别文件时不补。动作组名是推断的（Idle/Extra），
  VTS 热键里的触发关系（哪个键开哪个表情）不导入。
- 2× 渲染的 CPU 约为 1× 的 2~3 倍（8 线程）；嫌占用高可 `L2D_UI_SCALE=1`（回到 1× 渲染 + 放大，略糊）或 `--threads` 调小。

### 11.x 窗口位置与启动（2026-10-10）

- **启动不再"先大后小"**：桌宠窗口创建后先不映射，等 `SetZoom`（配置里的大小）到来、尺寸定好再一次性显示；
  1.5s 内没等到才按当前尺寸兜底显示。
- **位置记忆**：拖动挪窗、缩放后自动存 `pos_l`（窗口左边 x）/ `pos_b`（窗口底边到屏幕底的距离，像素），下次启动原位出现
  （钳进 `_NET_WORKAREA`）。没存过 → **工作区左下角**（任务栏/Dock 之上）。
- **缩放锚点**：底边不动；水平方向——贴左边（≤8px）则左边不动、贴右边则右边不动，否则中点不动（贴角落的桌宠缩放后仍贴角落）。
- 只改了 X11 桌宠端口（`PortX11Pet`）；GLFW 端口（Win/mac）仍是旧行为。

## 12. UI 架构：一个工程只用一套 UI 栈——EUI-NEO 常驻进程 `l2dpet-ui`（2026-10-09 夜）

**为什么换**：原设置窗口是 Xlib + Xft 手写自绘——固定 760×660 逻辑像素、不能响应式、只能跑 Linux/X11、
每 0.5s 整窗重画（先贴背景再画字，合成器取到中间帧就闪）。用户要求 PC 三平台，选定
[EUI-NEO](https://github.com/sudoevolve/EUI-NEO)（注意：它是 **C++17**，不是纯 C；Apache-2.0；GLFW/SDL2 + OpenGL/Vulkan）。
随后要求"一个工程 UI 栈只用一个"：右键菜单、托盘、说话气泡也全部搬进 EUI 进程。**2026-10-09 深夜定案回退：
说话气泡改回桌宠进程 X11 直绘**（用户拍板：旧版设计是对的——椭圆鼓泡 + 深青描边 + 下弯浅蓝 + 右上高光 +
两个小圆点沿法线指向角色 + 0.18s 淡入/0.22s 淡出；EUI 复刻两轮都不满意，直接从 git 复活 `RenderBubbleBg`
SDF 像素渲染全套：Xft 文字、选项胶囊、悬停、`PollChoice` 走 X 窗口事件）。右键菜单、托盘、设置窗口仍在 EUI 进程
（`PetPanel.hpp` X11 菜单/面板、`PetTray.hpp` GDBus 托盘已删除，CMake 不再链接 gio）。

**结构**：

```
桌宠进程 l2dtest --pet —— 只负责：角色窗口（透明、逐像素点击穿透 XShape）、渲染、鼠标输入、协议端口、
   │                            说话气泡（X11 ARGB 小窗直绘）+ 点击/滑动特效（帧上叠画）
   │  127.0.0.1:<ctl 端口>  桌宠协议 JSON Lines（和 LLM agent 同一条路）
   │  ① 推 ui_* 事件（右键菜单 / 打开设置）     ② 收 UI 发来的普通协议命令
   ▼
l2dpet-ui（live2d/panel/，EUI-NEO，常驻；主窗口启动隐藏、关闭=隐藏）
   ├─ 托盘：显示/隐藏角色、状态与设置…、总在最前✓、鼠标穿透✓、模型（单选子菜单）、退出
   ├─ 右键菜单：弹出式子窗口（_NET_WM_WINDOW_TYPE_POPUP_MENU），6 级菜单（主菜单/表情/动作/大小/不透明度…）
   └─ 状态与设置主窗口：状态 / 行为 / 窗口与模型 / 对话(LLM) / 记忆 / 关于 / 交互日志
```

**两条连接**（`petlink.cpp`，POSIX + Winsock）：
- 轮询连接：每 0.4s `{"cmd":"panel_state"}`（内容变了才 requestUpdate），界面操作排队发
  `config / touch / mood / emotion / model / llm_config / panel_request / choice / window / quit`。
- 事件连接：`{"cmd":"subscribe","role":"ui"}`，只保留 `"event":"ui_…"` 行。`role:"ui"` 的订阅由 `CtlServer::MarkUi`
  标记，**不计入"LLM 已连接"数**（`SubscriberCount()` 排除 UI 连接）；agent 端也忽略 `ui_*` 事件。

**`ui_*` 事件**（桌宠 → UI，坐标都是屏幕物理像素）：

| 事件 | 字段 | 含义 |
|---|---|---|
| `ui_menu` | `x` `y` `scale` `time` `wa`[4] | 右键：在 (x,y) 弹菜单；`time` = 右键的 X 事件时间戳；`wa` = 工作区（`_NET_WORKAREA`）|
| `ui_close_menu` | — | 在角色身上左键 = 收起菜单（兜底）|
| `ui_close` | — | 收起设置窗口与菜单（`panel page:-1`）|
| `ui_open` | `page` | 打开"状态与设置"某页 |

> `ui_bubble` / `ui_bubble_anchor` / `ui_bubble_hide` 已停用（气泡回到桌宠进程直绘，见上）。

**新命令**（UI → 桌宠）：`{"cmd":"choice","index":n}`（气泡选项被点 → 桌宠照旧推 `choice` 事件给 LLM）、
`{"cmd":"window","visible":bool}`（显示/隐藏角色窗口；隐藏时不渲染）、`{"cmd":"quit"}`。

**启动 / 生命周期**（`PortX11Pet::LaunchUi`）：桌宠第一次 `SetPanelState` 时 fork+exec `l2dpet-ui`
（工作目录 = 程序目录，找得到 `assets/` 与 `l2dpet.png`），环境变量 `L2DPET_PORT`（`--ctl` 成功后 setenv）/
`L2DPET_PAGE`（-1 = 不显示主窗口）/ `L2DPET_UI_SCALE`。查找顺序：`L2DPET_UI` > 本程序同目录 > `../build-panel/` >
`~/l2d-build/build-panel/`。UI 进程退出则 `waitpid(WNOHANG)` 回收，下次右键/打开设置时重新拉起；桌宠退出时 SIGTERM 它；
UI 连上过桌宠后断开超过 10s 自行退出。也可以单独运行 `l2dpet-ui`（连不上时显示"没有连上桌宠"，每秒重连）。

**焦点（X11 / mutter 的防抢焦点）**：菜单窗口一弹出就失焦被关，是因为 WM 认为它"抢焦点"。做法：右键的 X 事件时间
作为菜单窗口的 `_NET_WM_USER_TIME`，再发 `_NET_ACTIVE_WINDOW`（source=1 应用）；打开后 0.3s 内的失焦不算；
点菜单外任意处（失焦）→ 关闭。气泡是 tooltip 类型、`focusOnShow(false)`，不抢焦点。

**EUI-NEO 补丁**：上游缺"弹出子窗口/窗口类型/运行中控制窗口/常驻 tick/托盘动态菜单"，补丁放仓库
`live2d/panel/eui-patches/`（基于固定提交 `782c569`），CMake 自动应用（本地源码已应用则跳过；FetchContent 用 PATCH_COMMAND），
内容见该目录 README。

- **响应式**：窗口宽 ≥760 逻辑像素 → 侧栏展开（图标+文字）、状态页两列；更窄 → 侧栏收成图标、卡片单列；
  滑块行在 <520 宽时标签和滑块上下排；按钮流放不下自动换行；每页在滚动容器里。
- **高分屏**：EUI 按 `glfwGetWindowContentScale`（X11 = Xft.dpi/96）缩放内容；菜单/气泡/主窗口初始尺寸乘桌宠传来的
  `scale`。2× 屏实测设置窗口 1800×1440 物理 = 900×720 逻辑、菜单 480×902。
- **字体**：系统 CJK 字体（Linux `fc-match sans-serif:lang=zh-cn`、Windows 微软雅黑、macOS 苹方；`L2DPET_FONT` 可指定），

- **视觉风格（2026-10-10，Interactive Product Demo）**：品牌渐变 粉 #FF7EB3 → 紫 #8B7CFF → 蓝 #58B4FF，主色 #7C6CFF；
