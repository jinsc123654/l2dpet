# DESIGN：手臂关节骨架（只在关节弯折）——替代"弯曲变形 bend"

（2026-10-09。起因：用户判定"手臂弹性弯曲完全是错误方向，只能在关节弯折"。
bend 已作为 bug 删除，见 §0。本稿是重新设计，§6 已拍板，按 J1→J5 实施。）

## 0. 已处理的 bug：bend（臂身弯成弧线）

- **错在哪**：bend 让旋转角沿臂轴**连续渐变**（角度 = 最大角 × t）并沿轴拉伸——
  等于把上臂、前臂、手当成一根软管来弯，**没有一个点是关节**。真实手臂（以及
  Live2D/Spine 的骨骼绑定）只在**肩、肘、腕**三处转，骨段本身是刚性的。
  "太吓人 / 软管绕头"就是这个错误模型的直接后果，钳角度只能掩盖、不能修正。
- **处理**（本轮已做，未提交）：渲染器删掉 `SetDrawableLimbBend` 和 `LimbRot` 里的 bend
  字段与分支（`soft-renderer` 回到 bend 之前的状态）；播放器删掉 bend 调用和
  `L2D_LIMB_STRETCH` / `L2D_LIMB_RIGID` 两个旋钮；`BODYINFO` 里的方式标记 `bend` 改成 `joint`。
- **过渡期行为**：`arm.r/arm.l` 只做**肩关节刚性旋转**（只在关节转，符合规则），
  上限 90°。**已知缺陷**：肩部接缝（"肩从袖子里飞出来"）还在，由 §3.3 解决。

## 1. 实测：手臂美术是怎么切的（决定方案）

| 模型 | 手臂网格 | 关节与网格的关系 |
|---|---|---|
| **Haru**（官方）| ArmRA 组：上臂 `D_PSD_09`(y .27~.55) / 前臂 `D_PSD_10`(y .06~.33) / 手 `D_PSD_08`(y −.02~.14)；ArmRB 组是作者画的**另一套姿势**（不透明度切换）| **关节恰好落在网格之间** → 可以做纯铰链：每段整网格刚性转 |
| **shuflle** | `ArtMesh514`（右）= **上臂+前臂一张**(115 顶点，y .055~.50)；手掌/袖口 403/408/409；手指 404~407 | 腕关节落在网格之间；**肘关节在一张网格内部** → 必须按顶点切段 |
| Hiyori/Mao 等 | 部件 12~25 个（有袖子、多套姿势）| 上线前逐个用 `drawinfo` 看（§5 J1）|

（工具：Core 直读 moc3，打印每个 drawable 的 id / 顶点数 / 包围盒 / 所属部件链。）

## 2. 目标

1. **只在关节转**：肩、肘、腕三个铰链，骨段刚性；网格只在关节两侧很窄的一条带里过渡（§3.2）。
2. **够得着脸**：靠**屈肘**而不是把整条胳膊甩上天——托腮、摸头、手到嘴边（举话筒）、
   挥手（真人挥手动的是肘和腕，不是肩）都是"肩 20~60° + 肘 90~140°"。
3. **LLM 好用**：既能给关节角，也能给"手放到哪"（IK），跨模型同一套指令。
4. **肩部无接缝**：肩关节的转心放对位置，再加肩部过渡带（§3.3）。

## 3. 方案

### 3.1 骨架提取（每模型一次，可被 profile 覆盖）

- **骨段**：每条手臂有 `upper`（上臂）、`fore`（前臂）、`hand`（手）三段；
  每段 = 一组 drawable，或者一张 drawable 里的部分顶点。
- **自动推断**（`parts` 已经有每条手臂的 drawable 名单）：
  1. **只取当前可见的那套**（不透明度 > 0）：Haru 的 ArmRB 那套不参与；
  2. 沿"肩→手"轴（部件最高点 → 最远点）把各网格按包围盒中心投影排序：
     **整网格能分进某一段的整段分**（Haru：三张网格对应三段，纯铰链）；
  3. 跨了多段的网格（shuflle 的 514）**按顶点切**：投影 t < t_肘 归上臂，其余归前臂；
     肘点默认取 t=0.5（解剖比例：上臂和前臂近似等长），profile 可调。
- **关节点锚在顶点上**：每个关节 = 当前帧若干个指定顶点的均值（比如肩 = 上臂顶端
  一圈顶点的中心，**再往下挪半个臂宽**，即肩关节的球心）。这样关节会跟着呼吸、
  物理摆动（shuflle 的 armR1~5 是物理输出）一起走，转心不会漂。
- profile 覆盖（推断不准时）：
  ```json
  "skeleton": { "arm.r": { "upper":[402], "hand":[403,408,409,404,405,406,407],
                           "elbowT":0.52, "shoulderDrop":0.5,
                           "limits":{ "shoulder":[-30,95], "elbow":[0,145], "wrist":[-35,35] } } }
  ```

### 3.2 渲染：两骨线性蒙皮（FK），过渡带限制在关节附近

- 渲染器从"每个 drawable 一个旋转"升级为**每个顶点一组（骨 A, 骨 B, 权重）**，
  在**静止姿态**算一次缓存；每帧把骨变换作用在 Core 给出的当前顶点上。
- 前向链：肩转 θs → 肘点跟着走 → 前臂转 θs+θe（绕新肘点）→ 腕点跟着走 →
  手转 θs+θe+θw（绕新腕点）。
- **权重**：远离关节的顶点**完全刚性**（权重 0/1）；只有关节两侧 ±b 的窄带
  （默认 b = 臂长的 4%）用 smoothstep 过渡——这就是骨骼绑定的"蒙皮"，弯折只
  发生在关节处。b=0 就是硬铰链：单张网格会在关节撕开或折叠，所以只有
  Haru 这种"关节在网格之间"的模型才能用 b=0。
- 不同网格天然分属不同骨段时（Haru），网格内全刚性，零过渡。
- 绘制顺序：前臂/手抬到身前时画在最上层（沿用 `onTop`）；上臂保持原层级（不压住肩部饰边）。
- 成本：每条手臂约 600 个顶点、每顶点一次 2×2 旋转加一次混合——相对整帧
  可以忽略（板上实测再确认）。

### 3.3 肩部接缝（过渡期遗留的问题）

接缝的成因：转心取在"上臂最高点 × 0.75"，上臂顶端的切口整个转出了衣服。修法：
1. **转心 = 肩关节球心**：上臂顶端截面中心再往下半个臂宽。上臂绕球心转时，
   顶端切口基本在原位附近打转，大部分被饰边/衣服盖住；
2. **肩部过渡带**：上臂顶端一小段（默认臂长的 6%）给"躯干骨"（不转）留一部分权重，
   让切口贴住躯干，只有很窄一圈被拉伸，而且藏在饰边下面；
3. **肩角按美术设上限**：shuflle 只画了垂手和饰边，肩上限先定 90°，超过要补美术。
   **够脸靠屈肘，不靠抬肩**（§2.2）。

### 3.4 指令接口（给 LLM）

- **关节角**（度，带上下限，超出钳住并在回复里标出）：
  `BODY arm.r.shoulder=40 arm.r.elbow=120 arm.r.wrist=10`
  - `arm.r` 保留为**简写**：等于"肩 = 值×90°、肘自动配合"（老指令不用改）。
- **IK（手放到哪）**：`BODY hand.r=mouth`（或 `hand.r=0.1,0.6` 模型坐标）。
  两骨 IK 解出肩角和肘角，**肘朝外**（2D 下两解里取远离身体中线的那个），
  解不到就伸到最近可达点，回复 `OK … 够不着，差 0.05`。
  - **命名锚点**（每个模型从包围盒/面部参数区自动算，profile 可覆盖）：
    `head_top / face / mouth / chin / chest / waist / hip / side / up / forward`。
- 关节通道都走已有的弹簧、动捕微动、`t=` 过渡时间（本轮未提交的那批改动）。
- **动作库改写到关节空间**：
  - `wave_big`：肩 70°、肘 60° ± 25° 往返（肘挥），不再整臂上下摆；
  - `think`：`hand.r=chin` + 歪头；
  - `cheer`：肩 85° + 肘 30°（举手时肘微屈，像真人）；
  - `mic`：`hand.r=mouth`（配合 `TALK`）。
- **能力反馈**：`BODYINFO` 每条关节通道给上下限；`LIST` 增加 `SKELETON=arm.r:fk+ik,arm.l:fk+ik`；
  没有骨架的模型（Wanko 等）不出这些通道，LLM 自然不会去用。

### 3.5 和作者绑定的关系（优先级不变）

作者动作素材 > **作者骨骼（多套手臂美术 + 关节链，见 §7）** > 作者参数绑定（yumi 的 armup）
> **我们的关节骨架**（只是兜底）。profile 里有 `armSets` 的一侧手臂完全走作者绑定，外加骨架让位；
`"rigid": false` 的模型（yumi）走作者参数。

## 4. 验证（每期必须给出证据）

- **关节性检查**（自动，host）：逐顶点量"刚性残差"——每段里任意两个顶点的间距
  在动作前后的变化，过渡带以外必须 < 1e-4。这一条直接证明"只在关节弯"，bend 就是在这里会被抓出来的。
- **接缝检查**：肩部饰边周围一圈像素与静止帧比较，背景透出（alpha 洞）的像素数 = 0。
- 板上截图：托腮 / 手到嘴边 / 挥手（肘挥）/ 欢呼 / 叉腰，分别在 shuflle、Haru 上各截一张。
- 回归：骨架通道全不设定时，输出与基线逐位一致（`m1-align.sh`）。

## 7. 复查结论（2026-10-09，用户问"这些手是不是扭曲的"）与作者骨骼

**是扭曲的**（`img/demo-arm-joints-shuflle-distortion.png`，板上实拍放大）——骨段确实刚性（残差 ~5e-8），
但"把一张垂手的 2D 画转到别的角度"本身做不出可信的大动作：
1. **手的正反/拇指方向错**：手只画了"下垂、手背朝前"一种，转过 90° 以上就像左右手装反（捂脸、托腮最明显）；
2. **肘部折痕**：上臂+前臂同一张画，肘过渡带只是把网格硬折——内侧挤扁、外侧尖角，像折纸不像肘；
3. **叉腰不像叉腰**：垂手画法转到腰前 = 手指张开搭在裙子正面。

所以外加骨架只能当**兜底**（小角度还行：挥手那种"掌心朝前"的角度可看）。大动作要靠作者为每种姿势画的手臂。

### 7.1 带骨骼的模型：Natori（官方样例）

本机模型的手臂参数普查（Core 直读 moc3）：Natori / Mao / Ren / Rice 都是"肩01→肘02→腕03"的旋转变形器链
（Live2D 的骨骼），其中 **Natori 最完整**：左 A/C/D、右 A/B/E 共 6 套手臂美术（pose3 分组互斥），
每套一条关节链，右手还有可换手型（Hand01/04/05/06）和指关节（Roll）。
作者 TapBody 动作就是"切一套手臂 + 在它的关节链上动"——手扶眼镜、举怀表、抚胸、侧伸托掌全都干净。

**接法**（profile `armSets`，`live2d/player/profiles/Natori/l2d.profile.json`）：
- 每套手臂：`show`（要显示的部件，**含子部件**——A 套前臂 `PartArmARFore` 不在 pose 分组里，不一起藏会留残影）、
  `shoulder/elbow/wrist/fingers`（这套的关节参数）、`params`（这套生效时压住的参数——**手型显示开关**，
  不设的话手臂半透明）。同一套手臂的不同手型拆成独立的套（B/B01、E/E06）。
- 指令：`BODY arm.r.set=B`（`auto` 交回模型自己的动作）；`arm.r.shoulder/elbow/wrist(/fingers)` 自动接到
  当前套的关节参数（单位 = 作者参数，Natori 是 ±30 左右的角度）。`LIST` 的 `ARMSETS=` 列出各套与描述。
- 动作：profile 的 `actions` 里用 `{"ch":"arm.r.set","anchor":"E","keys":[[0.06,1],[0.9,0]]}` 开"切套窗口"，
  再叠关节关键帧。Natori 写了 11 个（挥手/举手示意/捏下巴/推眼镜/整理领带/抚胸/执事礼/侧伸示意/摊手/掩口/双手介绍）。

**踩到的坑：pose 判"哪套可见"看的是部件同名的伪参数，不是部件不透明度**。只压不透明度时 pose 仍以为旧套可见，
每帧往旧套渐变一步（dt/0.2 ≈ 0.17），实测 E=0.83 / A=0.17 卡在交叉渐变 → 手臂半透明 + 旧手臂残影。
`HoldPart()` 同时压不透明度和同名伪参数后两者分别是 1.00 / 0（`L2D_DBG_BBOX=1` 看 `op=`）。

**实测**：板上 Natori **29~30fps**（舒芙蕾 7fps）；8 个动作上板全部正常（`img/demo-natori-author-rig-board.png`），
host 11 个动作（`img/demo-natori-author-rig-actions.png`）。

**给其它模型的路线**：Mao/Ren/Rice 同理写 `armSets`（每个 10 分钟：用 `parts` 工具看部件层级、用 PART 切出来看、
扫一遍关节方向）；舒芙蕾这种只有垂手美术的模型，大动作只能**补美术**（让作者加画手臂套 + 关节链）或继续用表情姿态。
